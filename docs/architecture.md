# Архитектура

## Слои

- `components` — Vue SFC с отображением и локальным состоянием интерфейса; отдельный CSS рядом.
- `store/notesStore.ts` — данные и операции CRUD/переноса. `workspaceStore.ts` — предпочтение раскладки; `noticesStore.ts` — текущее сообщение.
- `store/persistence.ts` — снимок данных; `legacyStorage.ts` — нормализация и миграция старого формата.
- `composables` — поведение с жизненным циклом Vue: поиск, выбор, меню, диалог, уведомления, textarea, сетка, сворачивание пути и перетаскивание.
- `utils` — дерево сущностей, ограничения операций, статусы, форматирование, поиск, SVG и геометрия drop; `storage.ts` — независимый адаптер localStorage и кэша.
- `types/notes.ts` — модели и контракты; `constants/storage.ts` — ключи и TTL кэша; `router` — маршруты и проверка разделов.

Поток изменения: событие компонента → action store → копия данных → проверка/изменение → запись снимка → замена реактивного состояния. При отказе сохранения исходное состояние остаётся прежним, показывается ошибка.

## Данные и хранение

Главная — корень дерева с parentId=null. Папки принимают папки, перечни и заметки. Задачи принадлежат только перечням; заметки не содержат дочерние элементы. order определяет порядок среди соседей. Перенос в себя/потомка и несовместимые типы запрещены. Групповой перенос сохраняет внутренний порядок; обмен меняет две позиции.

Новый формат — единая запись `my-notes:state` с `{ version: 1, state }`. Отдельно хранятся `my-notes:layout` и `my-notes:current`. Заметки не используют TTL. TTL применяется только явными вызовами setCachedItem/getCachedItem.

При первом запуске читаются старые `tasks`, `todo-folders`, `todo-checklists`, `todo-notes`. Старые задачи без перечня группируются в перечни «Задачи». Исходные ключи не удаляются. Новый снимок имеет приоритет при последующих запусках. Раскладка и раздел также учитывают прежние ключи.

## Маршруты и перенос на Nuxt

Маршруты: `/` и `/entry/:id`. Несуществующие разделы, адрес задачи и неизвестные пути ведут на главную. Поиск задачи открывает её перечень и подсвечивает карточку. Vercel rewrites в корневом vercel.json обеспечивают загрузку приложения по прямому адресу раздела.

Чистые utils и модели не зависят от Vue. Stores создаются в экземпляре Pinia, без глобального состояния между запросами. DOM, измерения и жесты подключаются при onMounted, освобождаются при демонтаже. При миграции на Nuxt нужно заменить маршрутизацию и точку входа; загрузку localStorage выполнять на клиенте с согласованным начальным состоянием для SSR. Проверка типов включает Vue-шаблоны.

## Стили и безопасность вывода

Стили используют BEM-классы; базовые правила и переменные общие. Не вставляйте пользовательские названия или описания в v-html или шаблон. Иконки — только доверенные статические SVG. Подсветка поиска состоит из текстовых сегментов и mark. При добавлении browser API обеспечьте очистку обработчиков, таймеров, анимаций и observers.
