# Архитектура

## Слои

- `components` — Vue SFC непосредственно в папке: шаблон, script setup и встроенный style scoped.
- `assets/icons` — Vue-компоненты иконок; `assets/styles` — глобальные стили.
- `store/notesStore.ts` — данные и операции CRUD/переноса/вставки. `clipboardStore.ts` — снимок копируемых деревьев в памяти до вставки или отмены. `workspaceStore.ts` — предпочтения раскладки и темы; `noticesStore.ts` — текущее сообщение.
- `utils/persistence.ts` — чтение и запись текущего снимка; `utils/normalizeState.ts` — проверка записей и корректности дерева.
- `composables` — поведение с жизненным циклом Vue: поиск, выбор, меню, диалог, уведомления, textarea, сетка, раскрытие задач, сворачивание пути, применение темы и перетаскивание.
- `utils` — дерево сущностей, ограничения операций, статусы, форматирование, поиск и геометрия drop; `storage.ts` — независимый адаптер localStorage и кэша.
- `types/notes.ts` — модели и контракты; `constants/storage.ts` — ключи и TTL кэша; `router` — маршруты и проверка разделов.

Поток изменения: событие компонента → action store → копия данных → проверка/изменение → запись снимка → замена реактивного состояния. При отказе сохранения исходное состояние остаётся прежним, показывается ошибка.

`utils/clipboard.ts` собирает независимый снимок выбранных деревьев без повторного копирования выбранных потомков. При вставке проверяет тип назначения, выдаёт новые UUID и переназначает связи parentId. Корни добавляются в конец назначения, внутренний order сохраняется. Обход итеративный, поэтому глубокие деревья не расходуют стек вызовов. ClipboardStore очищает буфер только после успешного сохранения через NotesStore; навигация не сбрасывает снимок. Буфер не записывается в localStorage.

## Данные и хранение

PWA управляется одним экземпляром usePwa в App и передаётся компонентам через PWA_KEY. EntryForm регистрирует реактивный признак изменённого черновика через useUnsavedChanges. Worker создаётся при сборке; кеш ресурсов не хранит данные заметок. Обновление активируется по выбору пользователя, перезагрузка других вкладок не выполняется. Подробности — [pwa.md](pwa.md).

Главная — корень дерева с parentId=null. Папки принимают папки, перечни и заметки. Задачи принадлежат только перечням; заметки не содержат дочерние элементы. order определяет порядок среди соседей. Перенос в себя/потомка и несовместимые типы запрещены. Групповой перенос сохраняет внутренний порядок; обмен меняет две позиции.

Текущий формат — единая запись `notes-app__state` с `{ version: 1, state }`. Отдельно хранятся `notes-app__layout`, `notes-app__current` и `notes-app__theme`. Префикс задаётся в constants/storage.ts. Заметки не используют TTL. TTL применяется только явными вызовами setCachedItem/getCachedItem.

Задача может содержать массив subtasks. Подзадача хранит id, value, status и completed; порядок задаётся массивом, самостоятельного маршрута и parentId нет. NotesStore изменяет её статус и пересчитывает родительский через utils/taskStatus.ts в одной транзакции. Прямое переключение задачи с подзадачами запрещено. Нормализация проверяет подзадачи и согласует агрегированный статус. При копировании вложенный массив клонируется с новыми id; удаление и перенос задачи включают его автоматически. Черновик формы изолирован от сохранённых данных и учитывается защитой PWA от обновления.

Поддерживается только снимок версии 1. Другие версии, повреждённый JSON и некорректные коллекции дают пустое состояние; прежние ключи не читаются. Статус задачи обязателен: pending, in-progress или completed; флаг completed согласуется со статусом. Нормализация исключает повреждённые и повторяющиеся записи, восстанавливает допустимых родителей контейнеров и разрывает циклы папок. Задачи без существующего перечня исключаются; новые перечни автоматически не создаются.

## Маршруты и перенос на Nuxt

Маршруты: `/` и `/entry/:id`. Несуществующие разделы, адрес задачи и неизвестные пути ведут на главную. Поиск задачи открывает её перечень и подсвечивает карточку. Vercel rewrites в корневом vercel.json обеспечивают загрузку приложения по прямому адресу раздела.

Чистые utils и модели не зависят от Vue. Stores создаются в экземпляре Pinia, без глобального состояния между запросами. DOM, измерения и жесты подключаются при onMounted, освобождаются при демонтаже. При миграции на Nuxt нужно заменить маршрутизацию и точку входа; загрузку localStorage выполнять на клиенте с согласованным начальным состоянием для SSR. Проверка типов включает Vue-шаблоны.

## Стили и безопасность вывода

Стили компонентов встроены в style scoped. src/assets/styles/style.css содержит светлую палитру, сброс и оформление документа; themes.css — тёмную палитру и переключение цветовых переменных. Геометрия списка принадлежит EntryList, состояния карточек — TaskCard и ContainerCard, варианты диалогов — BaseDialog. Для содержимого дочерних компонентов используется адресный :deep(). SVG-иконки — Vue-компоненты с единым корневым svg, декоративными aria-hidden/focusable и currentColor; родительские scoped-классы задают их размер и состояния. IconContainer выбирает вариант по данным store, IconMenu принимает типизированное имя действия. Только превью и маркер перетаскивания, создаваемые контроллером в document.body, оформляются через адресные :global() в NotesWorkspace.

Пользовательские названия и описания выводятся как текст. Иконки компилируются из шаблонов Vue; строковая генерация HTML не используется. Favicon остаётся статическим public/icon-app.svg. Лицензии иконок меню сохранены в [icons-menu.txt](licenses/icons-menu.txt); источники остальных рисунков отмечены в компонентах. Подсветка поиска состоит из текстовых сегментов и mark. При добавлении browser API обеспечьте очистку обработчиков, таймеров, анимаций и observers.
