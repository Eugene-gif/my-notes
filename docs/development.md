# Разработка и проверки

## Установка

Версия Node.js должна соответствовать engines в package.json; проверенная среда — Node.js 24.19.0. TypeScript ограничен веткой 5.9 для совместимости с vue-tsc. Зависимости фиксируются package-lock.json.

```sh
npm ci
cp .env.example .env
npm run dev
```

PowerShell: `Copy-Item .env.example .env`. Dev-сервер по умолчанию доступен только локально. `npm run dev:host` включает доступ из локальной сети через cross-env.

## Настройки окружения

| Переменная     | Значение по умолчанию | Назначение                                                                |
| -------------- | --------------------- | ------------------------------------------------------------------------- |
| VITE_APP_TITLE | My notes              | Название в интерфейсе и заголовке вкладки                                 |
| VITE_BASE_URL  | /                     | Базовый путь Vite и Router, например /my-notes/ для размещения в подпапке |

.env исключён из Git; .env.example хранит только пример. VITE_* попадают в клиентскую сборку — секреты туда не записывают. После изменения переменных перезапустите dev-сервер или пересоберите приложение.

## Стиль кода и инструменты

Стиль согласован с kino-home: стрелочные функции, отдельное объявление каждой переменной, camelCase для логики и PascalCase для компонентов. Helpers и composables экспортируются именованным списком в конце файла. Логические блоки разделяются пустыми строками, сложные обработчики шаблона выносятся в script setup. Обычные функции допустимы, когда нужен собственный this, например в DOM-моках тестов.

Используйте const, если привязка не меняется. let остаётся для таймеров, ресурсов жизненного цикла, счётчиков и состояния обхода. Изменение свойств объекта или массива само по себе не требует let.

- Oxfmt (.oxfmtrc.json) отвечает за оформление: табы с шириной 2, одинарные кавычки, точки с запятой, строка 100 символов, LF и отступ внутри script/style Vue. JSON и Markdown используют 2 пробела. HighlightText сохраняет значимые пробелы между сегментами текста.
- .editorconfig задаёт те же отступы, кодировку и окончания строк при ручном вводе в редакторе; он не заменяет форматтер или линтер.
- Oxlint (.oxlintrc.json) проверяет ошибки, неиспользуемые переменные, выражения функций, стрелочные callbacks, prefer-const и no-var. Команда lint завершается с ошибкой и при предупреждениях.
- vue-tsc проверяет типы, включая Vue-шаблоны. ESLint не подключён: для принятого стиля достаточно Oxfmt и Oxlint. Если понадобятся дополнительные правила eslint-plugin-vue для template, потребуется отдельно согласовать зависимости.

Oxlint проверяет script Vue, но не полноценные template-правила; его prefer-const не применяется к .vue. Привязки Vue проверяйте вручную с учётом шаблона. Поддерживаемые возможности: [Oxfmt](https://oxc.rs/docs/guide/usage/formatter/config-file-reference), [Oxlint Vue](https://oxc.rs/docs/guide/usage/linter/plugins), [prefer-const](https://oxc.rs/docs/guide/usage/linter/rules/eslint/prefer-const).

Генерируемые файлы, lockfile и .env* исключены из форматирования; .env* также исключены из линтинга. Неподдерживаемые параметры indent, vueIndentTemplate, scriptIndent, styleIndent, templateIndent, force и ignoreConfigFiles не используются. Алиас @/* задан через paths: ["./src/*"] без устаревшего baseUrl.

## Тесты

Структура `tests/src` повторяет `src`: components, composables, store, utils, router и App. Общие фикстуры и вспомогательные mount-функции находятся в корне tests. Компоненты проверяются через Vue Test Utils и jsdom; отсутствующие в jsdom browser API моделируются в setup.ts. Тесты проверяют наши контракты и поведение, а не реализацию Vue, Pinia, Router или других библиотек.

Регрессионные сценарии данных используют текущий формат снимка и Vitest. При изменениях проверяйте нормализацию данных, ограничения типов и циклов, групповые операции, отмену черновиков, отказ записи, задержку поиска и очистку ресурсов. Компоненты и их тесты располагаются непосредственно в components без индивидуальных подпапок.

jsdom не проверяет реальную геометрию, касания и верхний слой браузера. Дополнительно проверяйте приложение в браузере: CRUD всех типов; три статуса; поиск и переход; назад/вперёд и перезагрузка прямого адреса; мышь/касание и переносы; экраны 320/390 px; большие тексты и видимость кнопок; уведомления поверх модальных окон. Используйте отдельный browser context для тестовых данных.

## Хостинг

PWA проверяется на production-сборке через npm run preview; в dev service worker отключён. Установка, офлайн-навигация и обновление двух версий требуют настоящего браузера. Настройки и сценарии: [pwa.md](pwa.md).

Vercel использует Vite-сборку в dist и корневой vercel.json с перенаправлением SPA-маршрутов на index.html. Для другого хостинга с history router настройте аналогичный fallback. При размещении в подпапке согласуйте VITE_BASE_URL и fallback этого хостинга.
