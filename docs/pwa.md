# PWA

My notes можно установить на устройство и открывать отдельным окном. После первого запуска с интернетом и успешной установки service worker приложение открывается без сети, включая прямые адреса `/entry/:id`. Заметки, задачи, поиск, темы и сохранение продолжают работать локально.

## Установка

В меню пользователя выберите «Установить приложение». Если браузер поддерживает beforeinstallprompt, откроется его системный запрос; иначе приложение покажет инструкцию. На iPhone/iPad используется меню «Поделиться» → «На экран Домой». В установленном окне пункт установки скрывается. Поддержка зависит от браузера и платформы.

Для размещения требуется HTTPS. Для локальной проверки подходят localhost и 127.0.0.1.

## Сборка и кеширование

```sh
npm run build
npm run preview
```

`vite-plugin-pwa` генерирует `manifest.webmanifest`, `sw.js` и Workbox-файл в папке сборки. Конфигурация находится в `vite.config.ts`: стратегия generateSW, обновления prompt, автоматическая регистрация отключена. В dev-режиме service worker не регистрируется. Проверяйте production-сборку на отдельном origin от dev-сервера, чтобы старый worker не обслуживал разработку.

Кешируются собранные HTML, JS, CSS, шрифты и иконки. Навигация обслуживается кешированным index.html; API и пути к файлам исключены из SPA fallback. Произвольные сетевые ответы не кешируются. Старые записи кеша удаляются при активации новой версии. Кеш файлов приложения и localStorage с заметками независимы.

Манифест использует относительные id, start_url, scope и адреса иконок. Vite base и регистрация worker учитывают базовый путь. `npm run build:host` сохраняет сборку в public_html. При размещении в подпапке задайте VITE_BASE_URL с завершающим `/` и настройте серверный fallback внутри этой подпапки; файлы sw.js, манифеста и иконок должны выдаваться как реальные файлы. Vercel-конфигурация в репозитории предназначена для размещения в корне и задаёт no-cache для worker и манифеста.

## Обновления и черновики

После выбора «Позже» предложение можно вернуть через «Обновить приложение» в меню пользователя.

`App` один раз создаёт usePwa и предоставляет его через PWA_KEY. Обновления проверяются браузером при регистрации, при возвращении во вкладку и восстановлении сети. Проверки при возвращении ограничены одним запросом в минуту.

AppUpdatePrompt предлагает «Обновить» и «Позже». Перед активацией worker и перед перезагрузкой проверяются изменённые формы. Если есть черновик, сначала сохраните его или отмените изменения. Изменение текста обратно на исходный снимает блокировку. При ошибке сохранения форма остаётся открытой, поэтому защита продолжает действовать. Незавершённое обновление позволяет повторить попытку.

Другие вкладки не перезагружаются автоматически: после активации новой версии они предлагают обновиться отдельно, сохраняя открытые черновики. Закрытие/перезагрузка вкладки с изменённой формой также запрашивает подтверждение браузера, когда браузер поддерживает такой запрос. Незавершённые черновики не записываются в localStorage и не восстанавливаются после принудительного закрытия.

## Проверки

Vitest проверяет нашу регистрацию, установку, отказ/отмену, обновления, очистку обработчиков и защиту форм. jsdom не проверяет реальный service worker.

В браузере проверяйте production-сборку: первоначальное кеширование, перезагрузку с выключенной сетью, вложенные маршруты, CRUD и сохранность данных, установку, новую сборку поверх старой, отказ от обновления, черновики в нескольких вкладках, мобильную ширину и темы. Для проверки установки используйте DevTools → Application → Manifest; для кеша и worker — Service Workers и Cache Storage.

PWA не добавляет аккаунты, синхронизацию, резервное копирование и push-напоминания. Очистка данных сайта удалит локальные заметки и кеш. Перенос localStorage на IndexedDB не требуется для текущих возможностей.
